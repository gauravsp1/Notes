html4 vs html5 **********
New Elements and Attributes

HTML4:
Limited set of elements and attributes.
No semantic elements like <header>, <footer>, <article>, etc.

HTML5:
Introduces new semantic elements such as <header>, <footer>, <article>, <section>, <nav>, <aside>.
New form elements and attributes like <input type="email">, <input type="date">, <datalist>, <output>, <progress>, <meter>.

Multimedia Support

HTML4:
Requires third-party plugins like Flash or Silverlight for embedding audio and video.

HTML5:
Native support for audio (<audio>) and video (<video>) elements without the need for plugins.
New attributes for controlling multimedia, such as controls, autoplay, loop, and muted.

Graphics and Visuals

HTML4:
No native support for graphics.
Relies on plugins or images for graphical content.

HTML5:
Introduces the <canvas> element for 2D drawing.
Supports scalable vector graphics (SVG) directly in HTML.

4. Forms and Input Types

HTML4:
Basic form controls like text, password, checkbox, radio, etc.
Limited input types and validation.

HTML5:
New input types like email, url, number, range, date, datetime-local, month, week, time, search, tel, color.
Built-in form validation features.

5. APIs and Scripting

HTML4:
Limited built-in APIs.
JavaScript used for dynamic behavior and interaction.

HTML5:
Rich set of new APIs like Geolocation API, Web Storage API (localStorage and sessionStorage), Web Workers, WebSockets, and more.
Better support for offline web applications through the Application Cache.

6. Doctype Declaration

HTML4:
Complex and lengthy doctype declaration.

HTML5:
Simplified doctype declaration

7. Error Handling

HTML4:
Less forgiving syntax.
Stricter rules that often lead to broken pages if not adhered to.

HTML5:
More forgiving with syntax errors.
Browsers handle errors more gracefully.

8. Mobile and Responsive Design

HTML4:
No specific features for mobile or responsive design.
Relies on CSS and JavaScript for responsiveness.

HTML5:
Improved support for mobile and responsive design.
Introduction of the <meta name="viewport"> element for controlling layout on mobile browsers.

9. Deprecated Elements and Attributes

HTML4:
Contains many presentational elements and attributes like <font>, <center>, and attributes such as bgcolor, which are now considered outdated.

HTML5:
Deprecated many of the presentational elements and attributes in favor of CSS.
Encourages the use of CSS for styling and layout.

What <meta name="viewport"> Does ****
Tells the browser how to scale and size the page based on the device’s screen size.
Ensures that your layout is not zoomed out or rendered as a tiny desktop page on mobile.

Media queries allow you to apply different CSS styles based on the screen size, orientation, resolution, etc.

✅ Use media queries to adapt the layout to different screen sizes.

Script async / defer *****
Normally, when you include a <script> tag
The browser will:
Pause HTML parsing.
Download the script.
Execute the script.
Then continue rendering the page.

| Feature             | No Attribute       | `async`            | `defer`         |
| ------------------- | ------------------ | ------------------ | --------------- |
| HTML parsing paused | ✅ Yes              | ❌ No               | ❌ No            |
| Executes when ready | ✅ Immediately      | ✅ As soon as ready | ❌ After parsing |
| Order guaranteed    | ✅ Yes (but blocks) | ❌ No               | ✅ Yes           |
| Good for DOM access | ✅ Yes              | ❌ Not always       | ✅ Yes           |


Feature				async																		defer
Loading behavior	Script is loaded asynchronously												Script is loaded asynchronously
Execution timing	Script is executed as soon as it's ready, may interrupt HTML parsing		Script is executed after HTML parsing is complete
Execution order		Order of execution is not guaranteed (executes as soon as it's downloaded)	Scripts are executed in the order they are included in the document
Best for			Independent scripts like analytics											Scripts that rely on the DOM being fully parsed

When to Use:
async: Use for scripts that are independent of other scripts and the DOM, such as third-party scripts (e.g., Google Analytics or ads).
defer: Use for scripts that rely on the entire DOM being ready before execution (e.g., DOM manipulation scripts, libraries like jQuery).
<script async src="analytics.js"></script>
<script defer src="app.js"></script>

Without async or defer:- The script is fetched and executed immediately, as soon as the browser encounters it during parsing of the HTML.
The browser halts parsing when it encounters the <script> tag, fetches and executes script.js, and then continues parsing the HTML document.
It doesn't do it asynchronously.

Box-Model

Content/element - The content of the box, where text and images appear
Padding - Clears an area around the content. The padding is transparent
Border - A border that goes around the padding and content
Margin - Clears an area outside the border. The margin is transparent

box-sizing ****
content-box (default): Width and height apply only to the content area. Padding and borders are added to the outside, increasing the total size of the element.
border-box: The padding and borders are included within the specified width and height, making the total element size easier to predict and manage.


why we use box-model***********
The CSS box model is critical for determining the overall size and layout of an element. It controls how elements are sized, spaced, and aligned on a webpage. 
Proper use of the box model ensures that web pages are responsive, visually appealing, and maintain proper layout structure across various devices. 
Understanding it is essential for both layout design and debugging layout issues in web development.


The position Property *****
There are five different position values:
static(By Default): Elements are positioned according to the normal document flow.
relative: The element is positioned relative to its original place in the document flow.
fixed : is positioned relative to the viewport
absolute: is positioned relative to the nearest positioned ancestor.if an absolute positioned element has no positioned ancestors, it uses the document body, 
sticky : is positioned based on the user's scroll position.


Value		Behavior																	Use case
static		Default, follows the normal document flow.									General content placement.
relative	Positioned relative to its normal position, moves within document flow.		Slight adjustments or nudging of elements.
absolute	Positioned relative to its nearest positioned ancestor or the viewport.		Modals, tooltips, dropdowns, precise control.
fixed		Positioned relative to the viewport and does not move with scrolling.		Sticky headers/footers, floating elements.
sticky		Switches from relative to fixed after scrolling past a point.				Sticky navigation bars or sidebars.

block vs inline *****
A block-level element always starts on a new line and takes up the full width available
An inline element does not start on a new line and it only takes up as much width as necessary
The <div> element is a block-level and is often used as a container for other HTML elements

display: inline-block*********
The element does not start on a new line, just like inline elements.

Margins and paddings work on all sides.
The element behaves like an inline element in terms of flow (i.e., it stays in line with other elements),
but it can have dimensions (width/height) like a block element.

Grid CSS****
CSS Grid Layout is a powerful 2-dimensional layout system for the web, allowing you to create responsive layouts with ease.
It enables you to organize elements in rows and columns, providing more control over layout compared to older methods like floats or flexbox.

Advantages of display: grid

1. 🧭 Two-Dimensional Layout Control
Unlike Flexbox (which is 1D), Grid lets you control rows and columns at once.
You can create rows and columns that line up naturally.

2. 🎯 Precise Placement of Items
You can place elements anywhere in the grid — even non-sequentially.
Great for dashboards, magazine layouts, split screens, etc.

| Feature                 | Grid                 | Flexbox         |
| ----------------------- | -------------------- | --------------- |
| Layout Type             | 2D (row & col)       | 1D (row or col) |
| Best For                | Full page, dashboard | Toolbars, menus |
| Item placement          | Absolute control     | Flow-based      |
| Reordering layout       | ✅ Easy               | ⚠️ Hard        |
| Semantic layout (areas) | ✅ Yes                | ❌ No          |


Real-World Use Cases for Grid ****

Maintain structure, proper responsive
Responsive web page layouts
Admin dashboards
Photo galleries
Magazine/newspaper-style designs
Centering items both vertically and horizontally
E-commerce product listing pages
Split-screen interfaces (login/register, chat UIs)

CSS Specificity
If there are two or more conflicting CSS rules that point to the same element, the browser follows some rules to determine 
which one is most specific and therefore wins out.
Think of specificity as a score/rank that determines which style declarations are ultimately applied to an element.
The universal selector (*) has low specificity, while ID selectors are highly specific! 
0 *
1 element tag
10 Class
100 ID
1000 inline css
!important will override all css properties 
If the inline style includes !important, it has the highest priority and cannot be overridden by external or internal CSS, even if those rules also use !important.

More Specific Rules Win: When conflicting rules apply to the same element, the rule with the higher specificity value takes precedence.
Equal Specificity: If two rules have the same specificity, the last defined rule in the CSS will take precedence.
Importance of Order: In case of equal specificity, the order of the rules matters—the last one defined in the CSS will override the others.

em vs rem
em and rem are relative CSS units. em is relative to the parent element’s font-size, so nested elements can compound in size.
rem is relative to the root (html) font-size, giving consistent sizing across the page.
| Feature        | em                                 | rem                              |
| -------------- | ---------------------------------- | -------------------------------- |
| Relative to    | Parent element                     | Root element (`html`)            |
| Nesting impact | Multiplicative (can compound)      | Consistent, no compounding       |
| Use case       | Component-specific scaling         | Global font, spacing, layout     |
| Typical usage  | Padding, margin inside a component | Font-size, global spacing system |

| Unit    | Relative To                                    | Example                          |
| ------- | ---------------------------------------------- | -------------------------------- |
| **em**  | The **font-size of the parent element**        | If parent is 20px, `2em = 40px`  |
| **rem** | The **font-size of the root element (`html`)** | If `html` is 16px, `2rem = 32px` |

1.document.getElementById(id)
Purpose: Selects a single element by its unique ID.
Return Type: A single HTMLElement object, or null if no element with that ID is found.
Usage: Most efficient for selecting a unique element by ID.
const element = document.getElementById("header");

2. document.getElementsByClassName(className)
Purpose: Selects all elements that have a specific class.
Return Type: An HTMLCollection (live collection) of elements with the specified class.
Usage: Great for selecting multiple elements with the same class name.
const elements = document.getElementsByClassName('button');

3. document.getElementsByTagName(tagName)
Purpose: Selects all elements with a specific tag name.
Return Type: An HTMLCollection (live collection) of elements with the specified tag.
Usage: Useful when you need to select all instances of a certain element type, such as all <p> or <div> tags.
const paragraphs = document.getElementsByTagName('p');

4. document.querySelector(selector)
Purpose: Selects the first element that matches a CSS selector.
Return Type: A single HTMLElement object, or null if no matching element is found.
Usage: Allows for more complex selection, such as #id, .class, tag, or attribute selectors.
const allButtons = document.querySelector('.button');

// Select by ID
const header = document.querySelector('#header');

// Select by class
const textClass = document.querySelector('.text');

// Select by tag
const paragraph = document.querySelector('p');

// Select nested elements
    const firstListItem = document.querySelector('ul li:first-child');

const buttonHtml= document.querySelector("button")
buttonHtml.style.backgroundColor="red"

5. document.querySelectorAll(selector)
Purpose: Selects all elements that match a CSS selector.
Return Type: A static NodeList of all matching elements.
Usage: Useful for selecting multiple elements with more complex selectors. The result is a static NodeList that does not update when the DOM changes.
const allButtons = document.querySelectorAll('.button');

  border: 1px solid black;
  top: 0;

  left: 0;
  right: 0;

When you specify all four top, bottom, left, and right, the browser tries to stretch the element to fit those bounds

What Actually Happens
top: 0; bottom: 0; → stretches the height to fill the parent vertically
left: 0; right: 0; → stretches the width to fill the parent horizontally
