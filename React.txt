
What is React *****
React is a popular JavaScript library used for building user interfaces, primarily for single-page applications. It is maintained by Facebook 

One of the main ways it does that is by encouraging you to be declarative instead of imperative. 
You get to declare how your components should behave and look under different states, and React’s internal machinery handles the complexity 
of managing updates, updating the UI to reflect changes, and so on.

Reconciliation *****
Reconciliation is the process through which React updates the DOM. When a component's state changes, 
React has to calculate if it is necessary to update the DOM. It does this by creating a virtual DOM and comparing it with the current DOM. 
In this context, the virtual DOM will contain the new state of the component.

How does React work? ***********
React creates a virtual DOM. When state changes in a component it firstly runs a "diffing" algorithm, which identifies
what has changed in the virtual DOM. And only updates those changes in real DOM

Features of React *********

Component-Based Architecture:
React applications are built using components, which are the building blocks of the user interface.
Each component is a self-contained module that can manage its own state and logic.

JSX:

Unidirectional Data Flow:

Virtual DOM ********
React keeps a lightweight representation of the “real” DOM in the memory, and that is known as the “virtual” DOM (VDOM).
When the state of an object changes, VDOM changes only that object in the real DOM instead of updating all of the objects. 
The virtual DOM (VDOM) is an in-memory representation of Real DOM. The representation of a UI is kept in memory and synced with the “real” DOM. 
It’s a step that happens between the render function being called and the displaying of elements on the screen. 
This entire process is called reconciliation.

React uses VDOM, which makes the web applications run much faster than those developed with alternate front-end frameworks. 
React breaks a complex user interface into individual components, allowing multiple users to work on each component simultaneously, 
thereby speeding up the development time.

UseEffect ******
By using this Hook, you tell React that your component needs to do something after render. 
React will remember the function you passed (we’ll refer to it as our “effect”), and call it later after performing the DOM updates. 

It is a replacement for componentDidMount,componentDidUpdate,componentWillUnmount


useEffect accepts two arguments:
1. A function that contains the side effect code.
2. An optional dependencies array that specifies when the effect should re-run.

Dependencies Array:
The dependencies array is crucial for optimizing performance and controlling when the effect runs.

No dependencies: The effect runs after every render.
useEffect(() => {
    // This effect runs after every render
});

Empty dependencies array: The effect runs only once, after the initial render (componentDidMount).
useEffect(() => {
    // This effect runs only once, after the initial render
}, []);

Specific dependencies: The effect runs only when one of the dependencies changes.
useEffect(() => {
    // This effect runs when `count` changes
    document.title = `Count: ${count}`;
}, [count]);

Cleanup Function
If your effect requires cleanup, you can return a cleanup function from the effect. This function runs when the component unmounts or before the effect re-runs.

import React, { useState, useEffect } from 'react';

function Timer() {
    const [seconds, setSeconds] = useState(0);

    useEffect(() => {
        const interval = setInterval(() => {
            setSeconds((prev) => prev + 1);
        }, 1000);

        // Cleanup function
        return () => clearInterval(interval);
    }, []); // Empty dependencies array ensures this runs only once

    return (
        <div>
            <p>Seconds: {seconds}</p>
        </div>
    );
}

export default Timer;

useMemo ****
useMemo is a React hook that allows you to memoize a computed value. 
It helps optimize performance by preventing expensive calculations on every render if the dependencies have not changed. 
You use useMemo to memoize values that are the result of complex computations or transformations of props and state.

const memoizedValue = useMemo(() => computeExpensiveValue(a, b), [a, b]);

The first argument is a function that computes the value.
The second argument is an array of dependencies. The memoized value is recalculated only when one of these dependencies changes.

Use Cases:
Expensive Calculations: Avoid recalculating a value on every render if it involves a costly computation.
Referential Equality: Ensure that an object or array reference remains stable across renders, which can be useful for preventing unnecessary re-renders of child components.


useCallback ****
useCallback is a hook in React that is used to memoize functions.
This optimization can be particularly helpful in scenarios where the callback is passed down to child components, preventing unnecessary re-renders of those child components.
 This can be useful for performance optimization, especially in cases where a component re-renders frequently. 
 The useCallback hook returns a memoized version of the callback that only changes if one of the dependencies has changed.
 
const memoizedCallback = useCallback(() => {
  // your function logic
}, [dependencies]);

Callback Function: The function you want to memoize.
Dependencies: An array of dependencies that the callback relies on. The memoized function will only change if one of these dependencies changes.

When to Use useCallback
Performance Optimization: When you have a component that re-renders frequently, and you want to prevent unnecessary re-creation of functions.
Passing Callback Props: When you need to pass callback functions down to child components, and you want to avoid unnecessary re-renders of those child components.

Things to Keep in Mind
Overuse: Using useCallback everywhere can lead to unnecessary complexity. It's mainly useful for optimization in performance-critical parts of your application.
Dependencies: Make sure to include all dependencies in the dependency array. Missing dependencies can lead to bugs because the memoized function won't update when it should.

useCallback vs useMemo *****

Type of Memoization:
useCallback: Memoizes a function.
useMemo: Memoizes a value (result of a computation).

Typical Use Cases:
useCallback: Useful for memoizing event handlers or callback functions that you pass to child components.
useMemo: Useful for memoizing the result of expensive calculations or derived data that you want to avoid recomputing on every render.

Choosing Between useCallback and useMemo
Use useCallback when you want to memoize a function.
Use useMemo when you want to memoize a value resulting from a calculation.

Reasons to Clear setInterval or setTimeout ********
Avoid Memory Leaks:
If you don't clear a setInterval or a long setTimeout, it will continue to exist in memory, even if the component or object that initiated it has been removed
or is no longer relevant.
This can lead to memory leaks, where the JavaScript engine is holding onto resources that are no longer needed, which can degrade the performance of your application over time.

Prevent Unwanted Repeated Executions (setInterval):
setInterval will continue to execute the specified code at regular intervals indefinitely until it is cleared.
If you no longer need the repeated execution (e.g., when navigating away from a page or when a certain condition is met),
failing to clear the interval can result in redundant operations being executed, wasting CPU cycles.
This can cause bugs, such as duplicate event handling, unnecessary API calls, or unexpected UI behavior.

Avoid Delayed Execution (setTimeout):
Sometimes a setTimeout schedules a function to execute after a certain delay. If the function is no longer needed (for example,
if the user navigates away from a page or the condition that triggered it is no longer relevant), you should clear it to prevent code from running unexpectedly after the delay.

Performance Optimization:
Clearing unnecessary intervals or timeouts helps reduce unnecessary computations and keeps your application performant, especially in larger applications with frequent updates,
animations, or API calls.

Prevent Inconsistent State in UI Components:
In applications using frameworks like React, setInterval or setTimeout can cause issues if not properly managed.
For instance, if a component using a timer is unmounted without clearing the timer, the callback might try to update the state of a non-existent component, leading to errors.

error boundary react *******
Error boundaries are React components that catch JavaScript errors anywhere in their child component tree, log those errors, and display a fallback UI
instead of crashing the entire component tree. Error boundaries only catch errors in the components below them and do not catch errors inside the error boundary itself.
lifecycle methods-
static getDerivedStateFromError(error): This method is used to update the state so the next render shows the fallback UI.
componentDidCatch(error, info): This method is used to log the error information.

class ErrorBoundary extends React.Component {
  constructor(props) {
    super(props);
    this.state = { hasError: false };
  }

  static getDerivedStateFromError(error) {
    // Update state so the next render will show the fallback UI.
    return { hasError: true };
  }

  componentDidCatch(error, errorInfo) {
    // You can also log the error to an error reporting service
    logErrorToMyService(error, errorInfo);
  }

  render() {
    if (this.state.hasError) {
      // You can render any custom fallback UI
      return <h1>Something went wrong.</h1>;
    }

    return this.props.children; 
  }
}
Error boundaries do not catch errors in:
Event handlers (you need to use try/catch in event handlers).
Asynchronous code (e.g., setTimeout or requestAnimationFrame callbacks).
Server-side rendering.
Errors thrown in the error boundary itself.


Pure Component *******
A Pure Component in React is a type of component that implements a shallow comparison of props and state to decide whether the component should re-render. 
This can optimize performance by avoiding unnecessary re-renders when the props and state have not changed.
A React component is considered pure if it renders the same output for the same state and props.
If the value of the previous state or props and the new state or props is the same, the component is not re-rendered.

Benefits of Pure Components:
Performance Optimization:
By preventing unnecessary re-renders, pure components can improve the performance of your application, especially when dealing with large or complex component trees.

Predictable Rendering:
A pure component renders only when there are changes in props or state, leading to more predictable and optimized rendering behavior.

Controlled Vs Uncontrolled Component ***********
Controlled- In HTML, form elements such as <input>, <textarea>, and <select> typically maintain their own state and update it based on user input. 
In React, mutable state is typically kept in the state property of components, and only updated with setState().
We can combine the two by making the React state be the “single source of truth”. 
Then the React component that renders a form also controls what happens in that form on subsequent user input. 
An input form element whose value is controlled by React in this way is called a “controlled component”.
Uncontrolled- the value attribute is absent or it's default value and can be changed
Benifite- instant validation
input type file can be controlled
A controlled component has its state completely driven by React,
Uncontrolled components can maintain their own internal state. E.g., a textarea's value.


Controlled-
Key Points:
Single Source of Truth:
The component’s state is the single source of truth for the form data.
Real-time Updates:
The input values are updated in real-time with the component’s state.
Easy Validation:
Form validation and handling are straightforward because the state is fully controlled by React.

Uncontrolled Components-
Key Points:
Direct DOM Access:
The form data is accessed directly from the DOM using refs.
Less React Involvement:
The component does not manage the form state internally, leading to less React involvement.
Simpler Code:
For simple forms, uncontrolled components can result in less code as you don’t need to manage state explicitly.

State Management:
Controlled: The state is managed by the React component.
Uncontrolled: The state is managed by the DOM.

Form Handling:
Controlled: More suitable for complex forms with validation, conditional fields, and dynamic changes.
Uncontrolled: Suitable for simple forms where direct DOM access is sufficient.

Validation and Formatting:
Controlled: Easier to implement validation and formatting as you have complete control over the form data.
Uncontrolled: Requires additional handling for validation and formatting as data is retrieved directly from the DOM.

Code Complexity:
Controlled: Can result in more boilerplate code due to state management.
Uncontrolled: Simpler and less code for basic forms.

Use Controlled Components:
When you need to control the form data in real-time.
When you need to implement complex form validation.
When the form data needs to be manipulated or transformed before submission.
When you need to dynamically enable/disable fields or change their values based on user interaction.

Use Uncontrolled Components:
When you have simple forms with minimal validation.
When you need quick access to form data without state management.
When you want to leverage the native form handling capabilities of the browser.

HOC(High order Component) ***********

An HOC is a function that takes a component as an argument and returns a new component that wraps the original one.
This allows us to add additional behavior or props to the wrapped component.
Its used to enchance the input component and is reusable.
it is used to share common functionality between component without repeating code
These functions are pure, which means they are receiving data and returning values according to that data.

When to Use HOCs

HOCs are useful in scenarios where you need to:
Share common logic between multiple components.
Abstract away complex behavior and keep components simple.
Implement cross-cutting concerns like authentication, logging, performance monitoring, etc.

Benefits of HOCs

Code Reusability:
HOCs promote the reuse of logic across multiple components, reducing redundancy and making the codebase more maintainable.

Separation of Concerns:
HOCs help separate the business logic from the UI components, leading to cleaner and more focused components.

Flexibility:
You can use HOCs to add multiple layers of functionality to a component, making them highly flexible and adaptable.

Common Use Cases
Access Control:
Implementing authentication checks to render components conditionally based on user roles or permissions.

Data Fetching:
Managing data fetching logic, such as making API calls and handling loading states.

Performance Optimization:
Adding memoization or caching to prevent unnecessary re-renders and improve performance.

Enhancing Component Behavior:
Adding behavior like logging, error handling, analytics, etc.

Render Props  ***********
Render Props is a pattern in React where a function is passed as a prop to a component, and the component uses this function to determine what to render.
It's a way of sharing logic between components while maintaining reusability and flexibility.
The term "render props" refers to a function prop that a component uses to "render" something dynamically based on what is passed to it.

Instead of passing static content or JSX, you pass a function as a prop, and the receiving component calls this function, typically passing some data back to it.
This allows you to control what should be rendered.
The main idea is that instead of hardcoding the component's children or markup, you pass a function to the component, which decides how it should render its UI.
Instead of creating a new Higher-Order Component (HOC) to share logic between components, 
you can use the render props pattern to achieve similar flexibility without creating new components.

function Counter({ render }) {
    const [count, setCount] = useState(0);

    const increment = () => {
        setCount(count + 1);
    };

    return render({ count, increment });
}

function App() {
    return (
        <div>
            <h1>Counter Example with Render Props</h1>
            <Counter render={({ count, increment }) => (
                <div>
                    <p>You clicked {count} times</p>
                    <button onClick={increment}>Click me</button>
                </div>
            )} />
        </div>
    );
}

Advantages of Render Props:
Reusability: By abstracting the logic (like mouse tracking, authentication, etc.) and passing a function to determine what should be rendered, 
			you make the component highly reusable.
Flexibility: The parent component fully controls how the child component renders based on the shared state or logic.
No Component Hierarchy Changes: Unlike HOCs, render props don't need to wrap components. They don't alter the component tree, making debugging easier.

Drawbacks of Render Props:
Prop Drilling:
If many components depend on the same behavior, you may find yourself passing the render prop down multiple layers, which can result in prop drilling.

Performance:
A new function is created on every render because the render prop is usually defined inline.
This can lead to performance issues unless optimizations like React.memo are used.

Both Higher-Order Components (HOCs) and Render Props are ways to share logic between components, but they do it differently:
HOC: Enhances a component by wrapping it and passing new props.
Render Props: Allows dynamic control over what is rendered by passing a function as a prop.


React.memo() *****
React.memo is a higher-order component that optimizes functional components by memoizing their rendered output.
This means that React will only re-render the component if its props change.
If the props remain the same, React will skip rendering the component and use the previously cached result.

function MyComponent({ name }) {
//Component
}
export default React.memo(MyComponent);


uesMemo ****
useMemo is a hook that memoizes the result of a function. It is used to optimize expensive calculations by caching the result and 
only recalculating it when the dependencies change.
useMemo can help prevent unnecessary re-renders by memoizing values or objects used in the component.
When you have expensive calculations or functions that you want to avoid recalculating on every render.
When you need to memoize objects or arrays to prevent unnecessary re-renders of child components.


React.memo() vs uesMemo ****

Purpose:
React.memo: Used to memoize entire functional components to prevent re-renders when props have not changed.
useMemo: Used to memoize the result of a function or value to avoid recalculating it on every render.

Usage Context:
React.memo: Wraps a functional component.
useMemo: Used within functional components to memoize values or calculations.

Performance:
React.memo: Reduces the number of renders for a component.
useMemo: Reduces the number of recalculations for a value or result.

Life Cycle Methods of react ***********


Mounting--
constructor(props):
Called before the component is mounted.
Used to initialize state and bind event handlers.
constructor(props) {
  super(props);
  this.state = { count: 0 };
}

componentDidMount()
This method is called after the component gets mounted on the DOM. 
Like componentWillMount, it is called once in a lifecycle. 
Before the execution of this method, the render method is called (i.e., we can access the DOM). 
We can make API calls and update the state with the API response.


Updating--
shouldComponentUpdate()
This method determines whether the component should be updated or not. By default, it returns true. 
But at some point, if you want to re-render the component on some condition, then shouldComponentUpdate method is the right place.

componentWillUpdate()  --- Deprecated 
It is called before the re-rendering of the component takes place. It is called once after the ‘shouldComponentUpdate’ method. 
If you want to perform some calculation before re-rendering of the component and after updating the state and prop, 
then this is the best place to do it.

componentDidUpdate()
This method is called just after the re-rendering of the component.
After the new (updated) component gets updated on the DOM, the ‘componentDidUpdate’ method is executed.
This method receives arguments like prevProps and prevState.

Unmounting--
componentWillUnmount()
This method is called before the unmounting of the component takes place.
Before the removal of the component from the DOM, ‘componentWillUnMount’ executes. This method denotes the end of the component’s lifecycle.

Error handling--componentDidCatch

useEffect has replaced componentDidMount, componentDidUpdate, and componentWillUnmount


componentDidMount: Called after the component is rendered for the first time.
useEffect(() => {}, []): Equivalent to componentDidMount. Runs after the first render.

componentDidUpdate(prevProps, prevState): Called after the component updates.
useEffect(() => {}): Runs after every render by default.
To replicate componentDidUpdate, use useEffect with dependencies. Example: useEffect(() => {}, [prop1, prop2]).

componentWillUnmount: Called before the component is removed from the DOM.
useEffect(() => { return () => {} }, []): Return a cleanup function to run before unmounting.

shouldComponentUpdate(nextProps, nextState): Allows you to control when the component should re-render. Use React.memo for functional components.

componentWillUnmount equivalent in hooks****
To do the cleanup after the component unmounts, we have a simple way to perform the equivalent of the componentWillUnmount using the useEffect Hook.
The only thing that we need to do is to return a function inside the callback function of the useEffect Hook, like this:

useEffect(() => {
  window.addEventListener("mousemove", () => {});
  return () => {
    window.removeEventListener("mousemove", () => {})
  }

React portal ********
React Portal is a feature that allows you to render children into a DOM node that exists outside the DOM hierarchy of the parent component.
This means you can render a child component at a different place in the DOM tree, which can be useful for scenarios like modals, tooltips, and other overlays.

import React, { useState } from 'react';
import ReactDOM from 'react-dom';

function Modal({ children, onClose }) {
  return ReactDOM.createPortal(
    <div className="modal">
      <div className="modal-content">
        {children}
        <button onClick={onClose}>Close</button>
      </div>
    </div>,
    document.getElementById('modal-root')
  );
}

function App() {
  const [showModal, setShowModal] = useState(false);

  return (
    <div>
      <button onClick={() => setShowModal(true)}>Show Modal</button>
      {showModal && (
        <Modal onClose={() => setShowModal(false)}>
          <h1>Hello, I'm a modal!</h1>
        </Modal>
      )}
    </div>
  );
}

export default App;

In this example, Modal is a component that uses createPortal to render its children into a DOM node with the id 'modal-root',
which should be a div at the top level of your HTML file:

<div id="root"></div>
<div id="modal-root"></div>
