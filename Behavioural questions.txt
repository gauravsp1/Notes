25. Can you describe a situation where you faced a significant technical challenge? How did you overcome it?
Situation:
During one of our application builds, we encountered serious performance issues — the UI was lagging and data from the API was loading slowly, which hurt user experience.

Task:I was responsible for identifying the root cause of these performance bottlenecks and improving the overall responsiveness of the application.

Action:
I started by analyzing network requests using Chrome DevTools and identified multiple redundant API calls triggered on each component render.
To address this, I refactored the data-fetching logic to ensure each API was called only when necessary and introduced lazy loading for non-critical components
to reduce initial load time.
Additionally, I collaborated with the backend engineer to trim unnecessary payload data from the API responses, which reduced response size and improved fetch speed.
Finally, I restructured the component hierarchy so that API calls were distributed intelligently, only loading data when the corresponding component mounted.

Result:
These optimizations led to a 40–50% improvement in page load times and a noticeably smoother user experience.
The client appreciated the enhanced performance, and the same data-fetching strategy was later adopted as a standard practice in other modules.

3.Describe a situation where you disagreed with a team member. How did you resolve it?
Situation:
I once had a disagreement with a team member regarding the choice of state management in our application.
They preferred using the Context API for managing global state, while I advocated for Redux,
considering the increasing complexity and scalability requirements of our application.

Task:
The task was to choose the best state management solution that could efficiently handle the app’s current needs and future growth without
impacting performance or introducing complications in debugging and maintenance.

Action:
To resolve the issue, I suggested that we take a step back and objectively evaluate both options based on the project’s requirements.
We organized a meeting where we listed out the pros and cons of Redux and the Context API, discussing aspects like state management capabilities,
reusability, ease of debugging, and long-term maintainability.
We considered how each solution would impact performance and developer experience, keeping in mind the complexity of managing state in larger
applications versus smaller, isolated features.

Result:
After a thorough discussion, we reached a consensus that Redux would be the better option for managing the global and critical application state,
given its robust ecosystem and ease of debugging complex states.
However, we decided to use Context API for simpler, more isolated features that didn’t require extensive state management.
This hybrid approach allowed us to leverage the strengths of both solutions and ultimately improved our development efficiency.
Our decision also prevented potential bottlenecks down the line, as Redux handled the complex state transitions seamlessly.
