JavaScript

JavaScript is a high-level, dynamic, and interpreted programming language that is widely used for web development.

Key Characteristics of JavaScript

Interpreted Language:
JavaScript code is executed by the browser’s JavaScript engine line by line, making it an interpreted language. Unlike compiled languages,
JavaScript does not require a separate compilation step.

Dynamically Typed: 
JavaScript variables can hold values of any data type and the type of a variable can change during the execution of a program.

Object-Oriented: 
JavaScript is object-oriented but with a prototype-based inheritance model, unlike the class-based inheritance of languages like Java or C++.

First-Class Functions: 
Functions in JavaScript are first-class citizens, meaning they can be assigned to variables, passed as arguments to other functions, and returned from other functions.

Event-Driven:
JavaScript is designed to respond to user actions and events, such as clicks, key presses, and mouse movements, making it ideal for interactive web pages.

Asynchronous Programming: 
JavaScript supports asynchronous programming through callbacks, promises, and async/await, which is essential for tasks like network requests.

Runs in the Browser and on the Server:
While originally developed for client-side scripting, JavaScript can now also be used on the server side thanks to environments like Node.js.



Advantages of JavaScript
Fast and Efficient:
JavaScript runs directly in the client's browser, which means it can execute code quickly and provide immediate feedback to users.Unless outside resources are required,
JavaScript is unhindered by network calls to a backend server.

Reduced Server Load:
By handling tasks on the client side, JavaScript reduces the processing burden on the server. This can lead to better scalability and lower server costs.

Simplicity. JavaScript is relatively simple to learn and implement.

Rich Ecosystem
Libraries and Frameworks: JavaScript has a vast ecosystem of libraries and frameworks that simplify development.
Popular ones include React, Angular, Vue.js for front-end development, and Node.js, Express for back-end development.

without the need for compiling a program into machine-language instructions beforehand.

loosly type and strongly type ************
In programming languages, the concepts of loosely typed (also known as weakly typed) and strongly typed refer to how strictly a language enforces type constraints.
In loosely typed languages, type checking is less strict, and implicit type conversions (coercions) are often performed.
These languages tend to allow more flexibility in how variables are used, but this can sometimes lead to unexpected behaviors.

In strongly typed languages, type checking is more rigorous, and implicit type conversions are typically not performed or are restricted.
Variables are often explicitly bound to a specific type, and attempting to use a value of the wrong type can result in errors.

JavaScript is single-threaded by design to ensure simplicity and a responsive user interface, avoiding the complexities associated with multi-threading.

Callback Hell*****
Callback Hell refers to a situation in JavaScript where multiple nested callbacks are used to handle asynchronous operations, making the code difficult to read and maintain. 
It occurs when each callback depends on the result of the previous one, leading to deeply nested structures that resemble a "pyramid of doom."

function fetchData(url, callback) {
    setTimeout(() => {
        console.log(`Fetching data from ${url}`);
        callback(null, `${url} data`);
    }, 1000);
}

function processData(data, callback) {
    setTimeout(() => {
        console.log(`Processing ${data}`);
        callback(null, `processed ${data}`);
    }, 1000);
}

function saveData(data, callback) {
    setTimeout(() => {
        console.log(`Saving ${data}`);
        callback(null, `saved ${data}`);
    }, 1000);
}

// Example of Callback Hell
fetchData('https://api.example.com', (err, data) => {
    if (err) {
        console.error('Error fetching data');
    } else {
        processData(data, (err, processedData) => {
            if (err) {
                console.error('Error processing data');
            } else {
                saveData(processedData, (err, savedData) => {
                    if (err) {
                        console.error('Error saving data');
                    } else {
                        console.log('Success:', savedData);
                    }
                });
            }
        });
    }
});

How Promise works******
Promise is an object representing the eventual completion or failure of an asynchronous operation.
Promises provide a way to handle asynchronous operations more gracefully than traditional callback-based approaches.

Creating a Promise
A Promise is created using the Promise constructor, which takes a function (executor) with two arguments: resolve and reject. These functions are used to settle the Promise:
resolve(value): If the operation is successful, the promise is fulfilled with the value.
reject(reason): If the operation fails, the promise is rejected with the reason (typically an error message).

let myPromise = new Promise((resolve, reject) => {
    let success = true; // Simulate success or failure
    if (success) {
        resolve("Operation successful!");
    } else {
        reject("Operation failed.");
    }
});

Consuming a Promise
To handle the result of a Promise, you use the .then(), .catch(), and .finally() methods:

.then(onFulfilled, onRejected): Attaches callbacks for the success and failure cases.
.catch(onRejected): Attaches a callback for only the failure case.
.finally(onFinally): Attaches a callback that will be invoked regardless of the outcome.

Chaining Promises
Promises can be chained to handle multiple asynchronous operations in sequence. Each .then returns a new Promise, allowing for further chaining:

let promiseChain = new Promise((resolve, reject) => {
    resolve(1);
});

promiseChain
    .then((result) => {
        console.log(result); // 1
        return result + 1;
    })
    .then((result) => {
        console.log(result); // 2
        return result + 1;
    })
    .then((result) => {
        console.log(result); // 3
    })
    .catch((error) => {
        console.error(error);
    });

Promises with Async/Await
The async and await keywords provide a more readable and straightforward way to work with Promises.
An async function always returns a Promise. The await keyword is used to wait for the Promise to settle:
async await holds the code execution till the promise is completed. Async/Await is a fancier syntax to handle multiple promises in synchronous code fashion. 
When we put async keyword before a function declaration, it will return a promise and we can use await keyword inside it 
which blocks the code until promise it awaits resolves or rejects.

Promise.all()
Promise.all() takes an iterable of Promises (such as an array) and returns a single Promise that resolves when all the input Promises have resolved.
If any of the input Promises reject, the returned Promise immediately rejects with the reason of the first rejected Promise.

let promise1 = new Promise((resolve) => setTimeout(resolve, 1000, 'First'));
let promise2 = new Promise((resolve) => setTimeout(resolve, 2000, 'Second'));
let promise3 = new Promise((resolve) => setTimeout(resolve, 3000, 'Third'));

Promise.all([promise1, promise2, promise3])
    .then((results) => {
        console.log(results); // ["First", "Second", "Third"]
    })
    .catch((error) => {
        console.error(error);
    });

let promise1 = new Promise((resolve) => setTimeout(resolve, 1000, 'First'));
let promise2 = new Promise((_, reject) => setTimeout(reject, 2000, 'Error in Second'));
let promise3 = new Promise((resolve) => setTimeout(resolve, 3000, 'Third'));

Promise.all([promise1, promise2, promise3])
    .then((results) => {
        console.log(results);
    })
    .catch((error) => {
        console.error(error); // "Error in Second"
    });
When to use:

Parallel Execution: When you need to execute multiple asynchronous operations in parallel and wait for all of them to complete before proceeding.
All-or-Nothing: When you require that all promises succeed for your code to continue. If any promise fails, you want to handle that failure immediately.


Promise.race()
Promise.race() takes an iterable of Promises and returns a single Promise that resolves or rejects as soon as one of the input Promises resolves or rejects.
let promise1 = new Promise((resolve) => setTimeout(resolve, 1000, 'First'));
let promise2 = new Promise((resolve) => setTimeout(resolve, 2000, 'Second'));
let promise3 = new Promise((resolve) => setTimeout(resolve, 3000, 'Third'));

Promise.race([promise1, promise2, promise3])
    .then((result) => {
        console.log(result); // "First"
    })
    .catch((error) => {
        console.error(error);
    });

let promise1 = new Promise((_, reject) => setTimeout(reject, 1000, 'Error in First'));
let promise2 = new Promise((resolve) => setTimeout(resolve, 2000, 'Second'));
let promise3 = new Promise((resolve) => setTimeout(resolve, 3000, 'Third'));

Promise.race([promise1, promise2, promise3])
    .then((result) => {
        console.log(result);
    })
    .catch((error) => {
        console.error(error); // "Error in First"
    });
When to use:

First Resolved Wins: When you need the result of the first promise that resolves or rejects, and the others can be ignored or cancelled.
Timeout Handling: Implementing a timeout for a promise. You want either the result or an error indicating that the operation took too long.
Load the Fastest Response:. For example, if two servers provide the same data, you can race them and use the one that responds first.

Promise.allSettled()
Promise.allSettled() takes an iterable of Promises and returns a single Promise that resolves when all of the input Promises have settled (each may resolve or reject).
The returned Promise resolves with an array of objects that each describe the outcome of each Promise.

let promise1 = new Promise((resolve) => setTimeout(resolve, 1000, 'First'));
let promise2 = new Promise((_, reject) => setTimeout(reject, 2000, 'Error in Second'));
let promise3 = new Promise((resolve) => setTimeout(resolve, 3000, 'Third'));

Promise.allSettled([promise1, promise2, promise3])
    .then((results) => {
        console.log(results);
        // [
        //   { status: 'fulfilled', value: 'First' },
        //   { status: 'rejected', reason: 'Error in Second' },
        //   { status: 'fulfilled', value: 'Third' }
        // ]
    });
When to use:

Handle All Outcomes: When you need to know the outcome of all promises, regardless of whether they resolve or reject.
Resilience: Useful for running multiple operations where each should be completed and reported on, even if some fail.

Promise.any()
Promise.any() takes an iterable of Promises and returns a single Promise that resolves as soon as any of the input Promises resolves.
If all input Promises reject, the returned Promise rejects with an AggregateError containing all the rejection reasons.
let promise1 = new Promise((_, reject) => setTimeout(reject, 1000, 'Error in First'));
let promise2 = new Promise((resolve) => setTimeout(resolve, 2000, 'Second'));
let promise3 = new Promise((resolve) => setTimeout(resolve, 3000, 'Third'));

Promise.any([promise1, promise2, promise3])
    .then((result) => {
        console.log(result); // "Second"
    })
    .catch((error) => {
        console.error(error);
    });

let promise1 = new Promise((_, reject) => setTimeout(reject, 1000, 'Error in First'));
let promise2 = new Promise((_, reject) => setTimeout(reject, 2000, 'Error in Second'));
let promise3 = new Promise((_, reject) => setTimeout(reject, 3000, 'Error in Third'));

Promise.any([promise1, promise2, promise3])
    .then((result) => {
        console.log(result);
    })
    .catch((error) => {
        console.error(error); // AggregateError: All promises were rejected
    });
When to use:

First Successful: When you need the first promise that resolves successfully, and you don’t care about the rejections unless all promises fail.
Redundancy: Useful for fault tolerance, where you try multiple strategies or sources and proceed with the first successful result.

Promise.all(): Waits for all Promises to resolve or any to reject. Returns an array of results or the first rejection reason.
Promise.race(): Resolves or rejects as soon as one of the Promises resolves or rejects. Returns the value or reason of the first settled Promise.
Promise.allSettled(): Waits for all Promises to settle (resolve or reject). Returns an array of objects describing each Promise's outcome.
Promise.any(): Resolves as soon as any Promise resolves. Rejects if all Promises reject, with an AggregateError.

Promise.all(): Use when you need all promises to succeed and want to wait for all of them to complete.
Promise.race(): Use when you need the first promise to settle (resolve or reject) and proceed with its result.
Promise.allSettled(): Use when you need to handle the results of all promises, regardless of whether they succeeded or failed.
Promise.any(): Use when you need the first successful result among multiple promises and want to ignore rejections unless all promises fail.

Arrow functions, unlike traditional functions, do not have their own this context. Instead, they inherit this from the surrounding (lexical) scope. 
This means that the value of this inside an arrow function is determined by where the arrow function is defined, not where it is called.

Hoisting ********
Hoisting is JavaScript's default behavior of moving declarations to the top of the current scope (function or global scope) before code execution.
This means that you can use variables and functions before they are actually declared in the code.
All declarations (function, var, let, const and class) are hoisted in JavaScript, while the var declarations are initialized with undefined ,
but let and const declarations remain uninitialized.
They are in a "temporal dead zone" (TDZ) from the start of the block until the declaration is encountered. Accessing them before the declaration results in a ReferenceError.

For let and const they are stored in different way in seperate memory space in Script and not in Global 
so we cannot acces them without intializing them.

Temporal Dead Zone (TDZ)
The Temporal Dead Zone (TDZ) is the period between entering a scope and when a variable is initialized.
Variables declared with let, const, and class are hoisted but not initialized during the TDZ.
The TDZ exists to ensure that variables are not used before they are declared, which helps avoid unexpected behavior and bugs. 
It encourages cleaner, more predictable code by preventing the use of variables until they are properly initialized.

Accessing these variables in the TDZ results in a ReferenceError.
2 Golden Rules:
1. Variable declarations are scanned and are made undefined
2. Function declarations are scanned and are made available

var variables are hoisted but initialized to undefined.
let and const variables are hoisted but remain in the temporal dead zone (TDZ) until initialization.
Function declarations are hoisted entirely, allowing them to be used before their declaration.

Unlike function declarations, function expressions (when functions are assigned to variables) are not hoisted with their initialization. 
This is because they follow the variable hoisting rules.

Classes declared with the class keyword are not hoisted in the same way as functions. 
They behave more like let and const, existing in the temporal dead zone until the declaration is evaluated.


Lexical  scope **********
A lexical scope in JavaScript means that a variable defined outside a function can be accessible 
inside another function defined after the variable declaration. 
But the opposite is not true; the variables defined inside a function will not be accessible outside that function.
Inner functions can acces outer variables but outter cannot access inner function variables

In JavaScript, functions create their own scope. The variables defined inside a function are not accessible outside of it.
However, functions defined within another function have access to the variables of the outer function. This nested structure defines the lexical scope.

Key Points of Lexical Scope
Scope Chain:
When a variable is referenced, JavaScript looks up the scope chain starting from the innermost scope and moving outward until it finds the variable or reaches the global scope.

Function Scope:
Each function creates a new scope. Variables declared within a function are not accessible outside it.

Block Scope:
With ES6, let and const introduced block-scoped variables, which are only accessible within the block they are defined in (e.g., within a loop or an if statement).



Closure ***********
A closure in JavaScript is created when a function is defined inside another function, and the inner function has access to the variables of the outer function, 
even after the outer function has finished executing. 
In simpler terms, a closure allows an inner function to "remember" and access its lexical scope, even when the outer function is no longer active.

commonly used for data encapsulation, function factories, callbacks, and event handlers, and maintaining private variables.

When an inner function is returned from an outer function, it preserves the environment (or lexical scope) in which it was created. 
This environment includes any variables that were in scope at the time the closure was created.

function outerFunction() {
    let outerVariable = 'I am from outer';

    function innerFunction() {
        console.log(outerVariable);  // Accessing a variable from the outer scope
    }

    return innerFunction;
}

const closureFunc = outerFunction();  // outerFunction() returns innerFunction
closureFunc();  // Output: 'I am from outer'

Disadvantages
it uses more memory
Careful attention is needed to avoid accidental variable sharing in loops and similar constructs.

Lazy loading ****
Lazy loading is a design pattern and optimization technique used to improve the performance and resource management of applications, particularly in the context of web development.
It involves delaying the loading of non-critical resources until they are actually needed,
which can lead to faster initial load times and more efficient use of bandwidth and system resources.

How Lazy Loading Works
The main idea behind lazy loading is to load resources only when they are required. For instance, in a web application, images, scripts, or other components 
might only be loaded when they come into the user's viewport (i.e., they are visible on the screen).

const LazyComponent = React.lazy(() => import('./LazyComponent'));

Benefits of Lazy Loading
Improved Performance: By loading only the necessary resources initially, the initial page load time is reduced, making the application appear faster to users.
Reduced Bandwidth Usage: Only the resources that are needed are downloaded, which can save bandwidth, especially important for users with limited or slow internet connections.
Better Resource Management: Lazy loading can help in managing memory and CPU usage more efficiently, as fewer resources are loaded and processed at any given time.
Enhanced User Experience: Users get a quicker response time and the content they need without waiting for the entire page to load.


Disadvantages of Lazy loading:

Firstly, the extra lines of code, to be added to the existing ones, to implement lazy load makes the code a bit complicated.
Secondly, lazy loading may affect the website’s ranking on search engines sometimes, due to improper indexing of the unloaded content.


Lazy loading is a powerful optimization technique that can greatly enhance the performance and user experience of web applications. 
By delaying the loading of non-essential resources, you can reduce initial load times, save bandwidth, and improve the overall responsiveness of your application. 
Implementing lazy loading requires a thoughtful approach to determine which resources can be loaded on demand and ensuring that the user experience remains seamless.

event bubbling ********

Event bubbling is a mechanism in the DOM (Document Object Model) that describes how events propagate through the hierarchy of elements. 
When an event occurs on an element, it first triggers the event handler on that element, then it bubbles up to its parent elements, 
and continues until it reaches the root of the document or is stopped.
Event bubbling is a powerful feature of the DOM that allows events to propagate from child elements to parent elements.
You can stop this propagation using stopPropagation().
It's commonly used for event delegation, which helps improve performance and organization in JavaScript applications.
Instead of adding event listeners to multiple child elements, you can add a single listener to a parent element. This is efficient and helps manage events dynamically.
 
Advantages of Event Bubbling:
Efficiency: Reduces the number of event listeners required, especially for lists or dynamically generated content.
Cleaner Code: Helps keep the codebase organized by managing events at a higher level.

Disadvantages of Event Bubbling:
Unintended Effects: If not managed properly, it can lead to unexpected behaviors if both parent and child elements have event handlers for the same event.
Difficulty in Debugging: Event flow can become complicated, especially in large applications.

Event delegate **************
Event Delegation is basically a pattern to handle events efficiently. Instead of adding an event listener to each and every similar element, 
we can add an event listener to a parent element and call an event on a particular target using the . target property of the event object.

Event Capturing ******************
In event capturing, an event propagates from the outermost element to the target element. 
It is the opposite of event bubbling, where events propagate outwards from the target to the outer elements. 

Event Propogation **********
Event propagation is the process by which events travel through the DOM when they occur. There are two main phases of event propagation: capturing and bubbling.

Throttleing *****
Throttling ensures that a function is only executed at most once every specified time period, regardless of how often the event is triggered.
It limits the execution of the function to a fixed rate.
Use Case: Throttling is useful for events that are triggered frequently and you want to control the maximum rate at which the function is called, 
such as scroll or window resizing events.

function throttle(func, limit) {
	let inThrottle;
	return function(){
	if(!inThrottle){
		inThrottle=true
		func()
		setTimeout(()=>{
			inThrottle=false
		},limit)
	}
	
	}
	

}
const logScrollPosition = () => {
  console.log("Logging scroll position:", window.scrollY);
};

const throttledScroll = throttle(logScrollPosition, 100);

// Adding the throttled function to a scroll event
window.addEventListener('scroll', throttledScroll);

Aspect					Debouncing												Throttling
Purpose					Delays execution until after event stops firing.		Limits the execution to once per time interval.
Triggering				Function runs after the user stops triggering events.	Function runs at most once every interval.
Typical Use Cases		Search boxes, input fields, resize events.				Scroll events, API calls on window resizing.
Execution Frequency		Executes once after the delay.							Executes at regular intervals (e.g., every 100ms).
Implementation			Resets a timer after every event trigger.				Uses a flag to limit the rate of function calls.

Debouncing: Imagine you’re typing in a search box, and the search function only fires after you've stopped typing for a set amount of time (e.g., 500ms). 
Every keystroke resets the timer.
Throttling: Imagine you're scrolling through a page, and the scroll event handler only fires once every 100 milliseconds, no matter how fast or often you scroll.

When to Use:
Debouncing: Use it when you only want to execute a function after an event stops firing (e.g., after the user has finished typing).
Throttling: Use it when you want to limit how often a function is called while an event is continuously firing (e.g., to handle scroll events or resizing efficiently).


What is CORS issue *****
CORS stands for Cross-Origin Resource Sharing. It's a security feature implemented by web browsers to restrict web pages from making requests to a different domain 
than the one that served the original page. This restriction is in place to prevent malicious websites from accessing sensitive data from other websites without permission.

Origin: An origin is defined by the combination of scheme (protocol), domain, and port of a URL. For example, https://example.com and http://localhost:3000 are different origins.

Same-Origin Policy: By default, web browsers enforce the Same-Origin Policy, which means that a web page served from one origin cannot normally make requests to resources
from a different origin.

Cross-Origin Requests: When a web page tries to make a request to a different origin (cross-origin request), 
the browser sends an HTTP request with an Origin header indicating the origin of the requesting page.

CORS Headers: The server hosting the requested resource can include special HTTP headers in its response to indicate whether it allows cross-origin requests 
from the requesting origin. These headers include:

Access-Control-Allow-Origin: Specifies which origins are allowed to access the resource. It can be a specific origin, * (wildcard) to allow any origin, 
or null to disallow all cross-origin requests.

Access-Control-Allow-Methods: Specifies the HTTP methods (e.g., GET, POST, etc.) allowed when accessing the resource.

Access-Control-Allow-Headers: Specifies the HTTP headers allowed when accessing the resource.

Access-Control-Allow-Credentials: Indicates whether the resource supports credentials such as cookies or authorization headers in cross-origin requests.

Preflight Requests: For certain types of cross-origin requests (e.g., requests with custom headers or methods other than GET, POST, or HEAD),
the browser first sends a preflight OPTIONS request to the server to determine if the actual request is safe to send.
The server responds with CORS headers indicating whether the actual request is allowed.

Simple Requests: Requests that meet certain criteria, such as using only safe methods (e.g., GET, POST) and not including custom headers other than those allowed by the server, 
are considered simple requests and may not trigger a preflight request.

Encapsulation ******
Encapsulation is a fundamental concept in object-oriented programming (OOP) that restricts direct access to some of an object's components and
can prevent the accidental modification of data. In JavaScript, encapsulation is achieved primarily through the use of functions and closures,
as well as through classes and modules introduced in ES6.

Benefits of Encapsulation
Data Hiding: Protects the internal state of an object from unintended or harmful modifications.
Modularity: Makes the code more modular by separating concerns and responsibilities.
Maintenance: Easier to maintain and update the code since the internal implementation is hidden from the outside world.
Reusability: Encapsulated code can be reused in different parts of an application without modification.

Using Closures
Closures allow functions to have access to variables from an enclosing scope even after the enclosing function has finished executing.
This can be used to create private variables and functions.

function createCounter() {
    let count = 0; // Private variable

    return {
        increment: function() {
            count++;
            return count;
        },
        decrement: function() {
            count--;
            return count;
        },
        getCount: function() {
            return count;
        }
    };
}

const counter = createCounter();
console.log(counter.increment()); // 1
console.log(counter.increment()); // 2
console.log(counter.getCount()); // 2
console.log(counter.decrement()); // 1
// console.log(counter.count); // Undefined, count is private


In this example, count is a private variable that cannot be accessed directly from outside the createCounter function.
The only way to modify or access count is through the methods provided (increment, decrement, and getCount)

How to measure speed *******
https://web.dev/what-is-speed/

Core Web Vitals

Largest Contentful Paint (LCP):
Definition: Measures loading performance. It marks the point in the page load timeline when the main content has likely loaded.
Good Threshold: LCP should occur within 2.5 seconds of when the page first starts loading.

First Input Delay (FID):
Definition: Measures interactivity. It quantifies the delay between when a user first interacts with a page (e.g., clicks a button) and when the browser responds to that interaction.
Good Threshold: FID should be less than 100 milliseconds.

Cumulative Layout Shift (CLS):
Definition: Measures visual stability. It quantifies the amount of unexpected layout shift of visible page content.
Good Threshold: CLS should be less than 0.1.

Other Web Vitals
In addition to the core Web Vitals, there are other important metrics that contribute to overall user experience:
First Contentful Paint (FCP): Time from when the page starts loading to when any part of the page's content is rendered.
Time to Interactive (TTI): The time it takes for the page to become fully interactive.
Total Blocking Time (TBT): The sum of all time periods between FCP and TTI when the main thread was blocked for long enough to prevent input responsiveness.

Importance of Web Vitals
User Experience: Improving Web Vitals can lead to a better user experience by making websites load faster, respond quicker, and be more visually stable.
SEO: Google uses these metrics as part of its ranking criteria, so optimizing for Web Vitals can improve search engine visibility and ranking.
Performance Monitoring: They provide a standardized way to measure and monitor the performance of web pages.

Tools for Measuring Web Vitals
There are several tools and techniques to measure Web Vitals:
Lighthouse: An open-source, automated tool for improving the quality of web pages. It provides audits for performance, accessibility, progressive web apps, SEO, and more.
PageSpeed Insights: Provides insights into the performance of a web page on both mobile and desktop devices and provides suggestions on how to improve.
Chrome DevTools: Built into the Chrome browser, it offers a variety of tools for developers to analyze and debug web performance.
Web Vitals Extension: A Chrome extension that provides real-time feedback on the core Web Vitals metrics for any site you visit.
Search Console: Provides a Core Web Vitals report to help website owners understand how their pages perform based on real-world usage data (field data).

Example of Improving Core Web Vitals
Here's a brief overview of how you might improve each of the core Web Vitals:

Largest Contentful Paint (LCP):
Optimize images and videos (use modern formats, compress, lazy load).
Improve server response times (reduce time to first byte, use a CDN).
Minimize render-blocking CSS and JavaScript.

First Input Delay (FID):
Minimize JavaScript execution time.
Break up long tasks.
Use web workers to run heavy tasks off the main thread.

Cumulative Layout Shift (CLS):
Include size attributes on your images and video elements.
Ensure ads, embeds, and iframes have reserved space.
Avoid inserting content above existing content except in response to user interaction.
