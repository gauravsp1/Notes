Resource hinting is a technique used by web developers to optimize the loading of web pages by providing the browser with hints about the resources it will need in advance. 
By specifying resource hints, developers can guide the browser to prefetch, preload, or prioritize resources more efficiently, 
which can significantly improve page load performance and user experience.

Tree-shaking ******
Tree-shaking is an optimization technique used in modern JavaScript bundlers (like Webpack, Rollup, and Parcel) to eliminate dead or unused code
from the final bundle. The main goal of tree-shaking is to reduce the bundle size by removing any code that isn't actually used in the application,
making the application faster and more efficient.

Key Concepts of Tree-shaking:
Eliminating Dead Code: Tree-shaking detects and removes code that is written but never used or executed in the final output.
ES6 Modules: Tree-shaking relies on static analysis of ES6 (or ES2015) module syntax (import/export).
Unlike CommonJS (require), ES6 modules allow the bundler to determine at build time which pieces of code are actually being used.
Pure Functions: Tree-shaking works more effectively with pure functions and side-effect-free modules
(modules that don’t alter global state or have external side effects).

// utility.js
export function usedFunction() {
  return 'I am used!';
}

export function unusedFunction() {
  return 'I am unused!';
}

// main.js
import { usedFunction } from './utility';

console.log(usedFunction());

In this example:

usedFunction is imported and used in main.js.
unusedFunction is never imported or used.
When tree-shaking is applied during the build process, unusedFunction will be removed from the final bundle since it is never used in the application.

Benefits of Tree-shaking:
Reduced Bundle Size: Only the code that is actually used is included in the bundle, leading to smaller file sizes.
Improved Performance: Smaller bundles load faster, reducing the overall loading time for users.
Better Maintainability: Tree-shaking encourages developers to write more modular and efficient code by eliminating unused exports and dependencies.

Limitations of Tree-shaking:
Side Effects: If a module has side effects, it could prevent certain pieces of code from being tree-shaken.
The package.json file of a library can specify whether a file has side effects using the "sideEffects" field,
helping bundlers decide which modules are safe to remove.
CommonJS Modules: Tree-shaking is less effective with CommonJS modules because they are dynamically evaluated,
making it harder for bundlers to determine which parts are unused.


Bundler **************
Bundlers are tools that take multiple JavaScript (and other assets like CSS, images, etc.)
files and bundle them into a single or smaller number of output files, typically for the browser to consume.
They are crucial in modern web development to handle module dependencies, optimize performance, and provide a smooth development experience.

Key Functions of a Bundler:
Combining Files: Bundlers take your JavaScript files, along with other assets, and combine them into one or more bundles.
This reduces the number of HTTP requests that the browser needs to make.
Dependency Management: Bundlers resolve module dependencies. You can write modular code using import/export statements (ES6 modules) or require (CommonJS),
and the bundler takes care of how those modules are connected.
Optimizations:
Minification: Reduces file size by removing comments, white spaces, and shortening variable names.
Tree-shaking: Removes unused or dead code from the bundle (as explained earlier).
Code Splitting: Dynamically loads parts of the code (lazy-loading), reducing the initial bundle size.
Asset Handling: Bundlers can process and bundle non-JavaScript assets like images, fonts, CSS, and even precompiled files like SASS, SCSS, or TypeScript.

Why Use a Bundler?
Improved Performance: Minifies and optimizes code and assets, reducing the amount of data the browser needs to download.
Modularity: You can write modular code with imports/exports and let the bundler take care of resolving the dependencies.
Cross-Browser Compatibility: Bundlers can transpile modern JavaScript (ES6+) into older versions for compatibility with older browsers using tools like Babel.
Asset Optimization: Bundlers can optimize images, fonts, and other assets, resulting in smaller file sizes and faster load times.
Dev Tools Integration: Many bundlers offer features like hot module replacement (HMR) and source maps to improve the development experience.

What Is Webpack***

Webpack is a module bundler.
It starts from a single entry point (like src/index.js), and recursively bundles all dependencies (JS, CSS, images, etc.) into optimized output files (e.g., bundle.js).

1.Entry – Where Webpack Starts
// webpack.config.js
module.exports = {
  entry: './src/index.js',
};
Webpack begins bundling from this file and traces all import or require() calls to build the full dependency graph.

2.Modules – Every File is a Module
JS/TS files
CSS/SCSS files
JSON, images, fonts, even Markdown
Webpack treats every asset as a module and knows how to process them using loaders.

3. Loaders – Transform Non-JS Files
Loaders tell Webpack how to handle files that aren't plain JS.

4. Output – Where Bundled Files Go
output: {
  path: path.resolve(__dirname, 'dist'),
  filename: 'bundle.[contenthash].js'
}
All bundled assets go to /dist (or whatever you configure)
Filenames can be dynamic ([contenthash] helps with caching)

5. Tree-Shaking – Remove Unused Code
With ES6 modules, Webpack can detect and remove unused exports.

6. Code Splitting & Lazy Loading
Webpack supports dynamic imports for lazy loading chunks.





transpiler **************
A transpiler (short for "transformation compiler") is a type of compiler that takes the source code written in one programming language and
converts it into another language at the same level of abstraction.
Typically, a transpiler converts code from a newer or more advanced version of a language (like modern JavaScript, ES6+) to an older version (like ES5),
making the code compatible with environments that don’t support the new features.

How Transpilers Work:
Input Code: The developer writes code in a modern language or version (e.g., ES6, TypeScript).
Transpiler: The transpiler converts this code into an older or different version of the language.
Output Code: The resulting code is backward-compatible or adapted for a different environment (e.g., older browsers).

Babble *******************
Babel is a JavaScript compiler and toolchain that allows developers to write next-generation JavaScript (ES6/ES7 and beyond) and
transform it into backward-compatible JavaScript that older browsers can understand.
It ensures compatibility across a wide range of environments, especially legacy browsers that may not support newer JavaScript features.

How Babel Works:
Parse: Babel takes your source code and parses it into an Abstract Syntax Tree (AST). This is a structured tree representation of the code.
Transform: Babel then applies transformations to the AST based on the plugins or presets you have configured.
These transformations convert the syntax or add polyfills.
Generate: After transforming the AST, Babel generates back the modified JavaScript code (in ES5 or compatible form).

Babel is a toolchain that is mainly used to convert ECMAScript 2015+ code into a backwards compatible version of JavaScript 
in current and older browsers or environments
Babel is a JavaScript compiler and not a webpack loader. It compiles (transpiles) higher JavaScript code (ES6+) to lower JavaScript code (such as ES5).

Memory Leaks ****
A memory leak happens when your app keeps holding on to memory (variables, DOM nodes, listeners, timers, etc.) that’s no longer needed, preventing garbage collection.
You forget to “let go” of something after you’re done with it — so it stays in memory forever.

| Category                   | Example                                  | Why it leaks                  |
| -------------------------- | ---------------------------------------- | ----------------------------- |
| **Uncleared timers**       | `setInterval`, `setTimeout` not cleared  | Keeps callback alive forever  |
| **Unsubscribed listeners** | `window.addEventListener`, socket, etc.  | References stay after unmount |
| **Async side effects**     | Fetch calls updating unmounted component | Component state persists      |
| **Global references**      | Variables stored globally                | GC can’t clear them           |
| **Detached DOM nodes**     | Holding refs after removal               | Browser can’t free memory     |
| **Event emitters**         | Listeners never removed                  | Keeps closure alive           |

How to Handle Memory Leaks
1.Cleanup Side Effects (React useEffect)

2.Cancel Fetch / Async Calls
If an API response tries to update state after unmount → React warns:
“Can’t perform a React state update on an unmounted component.”

AbortController
useEffect(() => {
  const controller = new AbortController();

  fetch("/api/data", { signal: controller.signal })
    .then(res => res.json())
    .then(data => setData(data))
    .catch(err => {
      if (err.name !== "AbortError") console.error(err);
    });

  return () => controller.abort(); // cleanup
}, []);

What Is Caching *****
Caching is the process of storing frequently accessed data closer to the user or the application, so it can be reused quickly without recomputation or refetching.

The goal:
Reduce load time
Decrease network usage
Improve scalability
Lower server cost

| Level   | Technique                      | Stored Where  | Best For               |
| ------- | ------------------------------ | ------------- | ---------------------- |
| Browser | HTTP cache, Service Worker,    | Client        | Static assets, offline |
			LocalStorage / SessionStorage,Cookies
| CDN     | Edge caching                   | Edge servers  | Static files           |
| App     | Redis, Memcached               | Server memory | API results, sessions  |
| DB      | Query cache, materialized view | Database      | Expensive queries      |
| React   | SWR, React Query               | Client memory | API data reuse         |
| SSR     | ISR, HTML cache                | Server        | Pre-rendered pages     |
| Network | DNS cache                      | ISP/OS        | Host lookup speed      |
| Build   | Webpack / npm cache            | CI/CD         | Build speed            |
