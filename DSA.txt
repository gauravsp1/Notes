2. Non-linear Data Structures:

Trees
A hierarchical structure where each node has a parent and children.
Binary Tree: Each node has at most two children (left and right).
Binary Search Tree (BST): A binary tree where the left child is smaller than the parent and the right child is greater.
AVL Tree: A self-balancing BST where the height of subtrees differs by at most 1.
Heap: A specialized tree where the parent is either greater than (max heap) or less than (min heap) its children.
Trie: A tree structure used for efficient searching, particularly with strings.
B-trees: A balanced tree used in databases and file systems for large data sets

Graphs:
A collection of vertices (nodes) and edges (connections between nodes).
Can be directed (edges have a direction) or undirected.
Weighted Graphs: Edges have weights (e.g., representing distances).
Applications: Modeling networks, social media graphs, and shortest path algorithms (Dijkstra’s, BFS, DFS).

Sorting algorithms***

Bubble Sort
Description: Compares adjacent elements and swaps them if they are in the wrong order. This process is repeated until the list is sorted.
Time Complexity:
Worst Case: O(n²)
Best Case: O(n) (if the list is already sorted)
Space Complexity: O(1) (in-place)
Stable: Yes
When to Use: Simple to implement but inefficient for large datasets. Better suited for small lists or when the list is nearly sorted.

Merge Sort
Description: A divide-and-conquer algorithm that recursively divides the array into two halves, sorts each half, and then merges the sorted halves.
Time Complexity: O(n log n) for all cases (worst, best, and average).
Space Complexity: O(n) (due to the additional space for merging)
Stable: Yes
When to Use: Suitable for large datasets, especially when stable sorting is required or when sorting linked lists.

QuickSort
Description: A divide-and-conquer algorithm that selects a "pivot" element, partitions the array into two subarrays
(one with elements less than the pivot and one with elements greater than the pivot), and recursively sorts the subarrays.
Time Complexity:
Worst Case: O(n²) (occurs when the pivot is poorly chosen, e.g., always the smallest or largest element)
Best and Average Case: O(n log n)
Space Complexity: O(log n) (for recursive call stack)
Stable: No
When to Use: One of the most efficient algorithms for large datasets, though care is needed in pivot selection
(randomized pivot or "median of three" techniques can improve performance).

Heap Sort
Description: Uses a binary heap data structure to repeatedly extract the maximum (or minimum) element and rebuild the heap.
Time Complexity: O(n log n) for all cases (worst, best, and average).
Space Complexity: O(1) (in-place)
Stable: No
When to Use: Efficient when memory usage is critical, but it is not stable. Often used in priority queues and large datasets where stability isn't important.


Searching algorithms ***

1. Linear Search
Description: This is the simplest search algorithm where each element in the list is checked sequentially until the desired element is found
or the list is exhausted.
Time Complexity:
Worst Case: O(n) (n is the number of elements in the list)
Best Case: O(1) (if the element is at the start)
Space Complexity: O(1)
When to Use: Best for small or unsorted datasets. Works on any data structure (arrays, linked lists, etc.) and does not require the dataset to be sorted.

2. Binary Search
Description: A divide-and-conquer algorithm that repeatedly divides the sorted array in half, comparing the middle element with the target value.
If the middle element is greater or less, it narrows the search to the corresponding half.
Time Complexity:
Worst Case: O(log n) (where n is the number of elements)
Best Case: O(1) (if the middle element is the target)
Space Complexity: O(1) (iterative) or O(log n) (recursive)
When to Use: Requires the dataset to be sorted. Ideal for large datasets where the cost of sorting is justified or the data is already sorted.
