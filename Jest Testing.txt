import { render, screen, fireEvent } from '@testing-library/react';
import Login from './Login';
import loginApi from './loginApi';

jest.mock('./loginApi'); // mock the API

describe('Login Page', () => {
  test('successful login shows welcome message', async () => {
    // Mock API response
    loginApi.mockResolvedValue({ user: 'admin', token: 'fake-jwt' });

    render(<Login />);

    fireEvent.change(screen.getByPlaceholderText('Username'), { target: { value: 'admin' } });
    fireEvent.change(screen.getByPlaceholderText('Password'), { target: { value: '1234' } });
    fireEvent.click(screen.getByText('Login'));

    const message = await screen.findByTestId('message');
    expect(message).toHaveTextContent('Welcome admin');
  });

  test('failed login shows error', async () => {
    loginApi.mockRejectedValue(new Error('Invalid credentials'));

    render(<Login />);

    fireEvent.change(screen.getByPlaceholderText('Username'), { target: { value: 'wrong' } });
    fireEvent.change(screen.getByPlaceholderText('Password'), { target: { value: 'pass' } });
    fireEvent.click(screen.getByText('Login'));

    const message = await screen.findByTestId('message');
    expect(message).toHaveTextContent('Login failed');
  });
});

| Feature               | `fireEvent` ✅        | `userEvent` ✅                       |
| --------------------- | -------------------- | ----------------------------------- |
| Speed                 | Fast, low-level      | Slower but realistic                |
| Simulates typing      | One-shot change      | Character by character              |
| Simulates clicks      | Just fires `click`   | Focus + mouseDown + mouseUp + click |
| Good for              | Simple state changes | Realistic user flows                |
| Auto-wrapped in `act` | Yes                  | Yes                                 |


Act ***
act is a utility from React Test Utils that ensures all React state updates & effects are flushed before assertions.
It’s like saying: “Wait until React finishes updating the DOM after a state change, then continue.”
Without it, you might assert too early (before React has re-rendered).

When is it needed?
Whenever your component triggers state updates, effects, or async updates.

import { render, screen, fireEvent, act } from '@testing-library/react';
import Counter from './Counter';

test('increments counter with act', () => {
  render(<Counter />);
  
  act(() => {
    fireEvent.click(screen.getByText('+'));
  });

  expect(screen.getByText('1')).toBeInTheDocument();
});

Mock Data ****

Why Use Mock Data?
Avoid dependency on network/API → your tests run faster and are reliable.
Test different scenarios:
Success responses
Error responses
Empty responses
Helps you unit test components without needing backend.

1. For API calls
import loginApi from './loginApi';

jest.mock('./loginApi');

test("login success", async () => {
  // Mock data
  loginApi.mockResolvedValue({ user: "admin", token: "fake-jwt" });

  const data = await loginApi("admin", "1234");
  expect(data.user).toBe("admin");
});

Here:
mockResolvedValue() → returns mock data for async success.
mockRejectedValue() → simulate API failure.


2.For Component Props / State
const users = [
  { id: 1, name: "Alice" },
  { id: 2, name: "Bob" }
];

render(<UserList users={users} />);
